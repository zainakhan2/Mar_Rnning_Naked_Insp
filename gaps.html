G1: Mobile UX Checklist

✓ CLOSED HIGH

📍 Location: P4A workbook

Problem Identified:

Problem: No mobile QA standard. 60%+ of D2C traffic is mobile but most new Shopify stores are only tested on desktop.

Resolution:

Resolution: 15-point checklist embedded as a sheet in P4A. Test on iPhone SE (smallest) + iPhone Pro Max (largest) + Android mid-range. Run checklist before launch and after every theme change.

Protocol Details:

15-point mobile QA checklist covering: viewport meta tag, touch targets ≥48px, font size ≥16px, no horizontal scroll, ATC button above fold, sticky header, image lazy loading, form input zoom prevention, footer nav, search visibility, cart accessibility, checkout flow, payment buttons, order confirmation, email responsive.

G2: Site Speed Benchmarks

✓ CLOSED HIGH

📍 Location: P4A workbook

Problem Identified:

Problem: No performance baseline. Slow sites kill conversion — 1 second delay = 7% conversion loss.

Resolution:

Resolution: Benchmarks + monitoring protocol embedded in P4A. Monthly check on the 1st. Alert threshold: any metric in "Poor" range = immediate investigation.

Protocol Details:

Core Web Vitals targets: LCP <2.5s, FID <100ms, CLS <0.1. Monthly monitoring via PageSpeed Insights. Image optimization: WebP format, max 200KB/image. Lazy load below-fold images. Minimize Shopify apps (each adds 50-200ms).

G3: Launch Rescue Protocol

✓ CLOSED CRITICAL

📍 Location: P6E workbook

Problem Identified:

Problem: No contingency for a failed launch. Most GTM plans assume success; none plan for failure.

Resolution:

Resolution: 4-step rescue protocol with specific triggers (daily order count < 1 for 3 consecutive days). Embedded in P6E with escalation from Step 1 → Step 4.

Protocol Details:

4-step diagnostic for <5 orders in Week 1. Step 1: Traffic audit (GA4 — is anyone visiting?). Step 2: Conversion audit (are visitors adding to cart?). Step 3: Targeting audit (are the right people seeing ads?). Step 4: Price/offer test ($29.99 for 2 weeks, or add HERSTRIDE20 if not already active).

G4: Founder Compensation

✓ CLOSED HIGH

📍 Location: P7B workbook

Problem Identified:

Problem: No guidance on when/how the founder pays themselves. Common reason for founder burnout and premature business closure.

Resolution:

Resolution: 3-phase framework with cash floor ($3K minimum) embedded in P7B. Prevents both overpaying (draining the business) and underpaying (burning out).

Protocol Details:

Owner's Draw framework: Phase 1 (Month 1-6): $0 — reinvest everything. Phase 2 (Month 7-12): 10-20% of net profit as Owner's Draw. Phase 3 (Year 2+): 30-50% of net profit. Never draw if cash position <$3K. Monthly self-review: "Can the business sustain this draw for 3 more months?"

G5: Data Breach Response

✓ CLOSED MEDIUM

📍 Location: P8C workbook

Problem Identified:

Problem: No data breach response plan. Shopify handles PCI, but email lists, customer data in Klaviyo/GA4 are still vulnerable.

Resolution:

Resolution: 5-step protocol with GDPR-compliant timelines embedded in P8C. Annual review of data handling practices.

Protocol Details:

5-step protocol: (1) Contain — isolate affected systems, change all passwords. (2) Assess — determine scope, what data was exposed, how many customers affected. (3) Notify — affected customers within 72 hours (GDPR requirement), state AG if >500 records (varies by state). (4) Remediate — patch vulnerability, implement additional controls. (5) Document — incident report, lessons learned, policy updates.

G6: Product Recall Protocol

✓ CLOSED LOW

📍 Location: P8D workbook

Problem Identified:

Problem: No recall procedure despite product liability exposure (a belt that fails during a run could cause phone damage or injury).

Resolution:

Resolution: 4-phase protocol with supplier accountability clause in P8D Supplier Agreement. Product liability insurance ($300-500/yr) as financial backstop.

Protocol Details:

4-phase protocol: (1) Contain — stop all sales immediately, pull Amazon + Shopify listings. (2) Investigate — identify defect scope, affected batch/SKU, root cause. (3) Notify — email all affected customers, offer full refund + replacement, post notice on site. (4) Remediate — supplier corrective action, updated QC protocol, resume sales only after verification.

G7: Supply Chain Disruption

✓ CLOSED HIGH

📍 Location: P10CD workbook

Problem Identified:

Problem: Single-source manufacturing + single freight route = high concentration risk.

Resolution:

Resolution: 3 scenario playbooks with specific trigger events and response timelines. Backup supplier pre-identified (not contracted, but researched). Embedded in P10CD.

Protocol Details:

3 scenarios with playbooks: (1) Factory offline (fire, COVID, closure) — activate backup supplier within 72 hours, air freight existing inventory bridge. (2) Freight delay (port congestion, weather) — reroute via alternative port, air freight partial shipment for bestselling SKUs. (3) Customs hold (documentation error, inspection) — freight forwarder escalation protocol, pre-verified HS code 4202.92, maintain customs bond.

G8: Channel Abandonment

✓ CLOSED MEDIUM

📍 Location: P11B workbook

Problem Identified:

Problem: No criteria for when to stop investing in an underperforming channel. Common mistake: either abandoning too early (before optimization) or continuing too long (wasting budget).

Resolution:

Resolution: Triple-fail test with rescue-before-abandon approach embedded in P11B. 2-month observation window prevents premature abandonment.

Protocol Details:

Triple-fail test: a channel should be abandoned only if ALL three conditions are met for 2+ consecutive months: (1) ROAS < 1.0× (spending more than earning). (2) CAC > LTV (acquiring customers at a loss). (3) No strategic value (no brand building, no data, no audience growth). If only 1-2 conditions met: rescue protocol (budget reduction, creative refresh, audience pivot). If all 3 met: redirect 100% of that channel's budget to the best-performing channel within 2 weeks.
